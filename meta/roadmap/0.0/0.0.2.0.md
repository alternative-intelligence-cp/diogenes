# 0.0.2.0 — tasks: post with the room check and the spec at a blob, claim, progress, report, verify by another identity, repost; the credits runner wrapper — PLANNED (2026-10-10)

> **Scope:** DR-99, DR-100, DR-101, DR-102, DR-103, DR-104; RULES §1's three conditions; DESIGN §2.3, §10.2. The P0 core.
>
> **What it is not:** a dispatcher (Diogenes never chooses the executor); the board (0.5); subagent inboxes (0.1); a change to `nitpick-libs/.internal/credits/run.sh` (another project's tree, RULES §4): the runner's task mode is a **wrapper** shipped here that calls `run.sh` unchanged between `claim` and `report`.
>
> **Found at planning:** (1) DR-102's "spec at a blob hash" is derived by `dio` from git, not typed: `--spec PATH` resolves `HEAD:PATH` in the caller's checkout and refuses an uncommitted or unpushed spec (hazard 5's lesson applied to tasks). (2) The room check needs 0.0.2.1's `room(account)`; this subcycle ships `room()` returning `('unknown', 'no meters published yet')` for every account, and 0.0.2.1 replaces the body. (3) The claimer's account must equal the route account, or a Max subagent could claim a Team task by accident. (4) **Seats rotate often, and a task must outlive its poster's seat** (V-10): the worker's poster check asks whether the poster held the orchestrator role *when it posted*, and the role's current holder may verify and withdraw what a predecessor posted. DR-102 needs the poster to have been the orchestrator; it does not need it to still be. If the author prefers the strict reading (every open task of a rotated seat is refused and re-posted), that is his call, and it re-cuts only this step. (5) The "when it posted" check keys on the `role_event` that made the poster the holder, recorded at post as `task.poster_event`, not on the `at` timestamps: those have one-second resolution, and a post and a handoff inside the same second would otherwise refuse a genuine task (R-3).

**Gate for starting:** 0.0.1.1 `DONE`.

## 1. Commands

```
dio task post --project P --executor K --route ACCOUNT --model M --spec PATH[@BLOB] [--grace DUR] [--force] [--local]
dio task list [--project P] [--mine | --open | --reported | --stale | --all] [--json]
dio task show tN [--json]
dio task claim tN [--label LABEL]
dio task progress tN --note TEXT
dio task report tN --ref REF [--note TEXT] [--label LABEL]
dio task verify tN --verdict pass|fail --evidence REF [--label LABEL]
dio task repost tN
dio task withdraw tN --reason TEXT
```

### `post` (DR-99, DR-102, DR-103)
1. Caller resolved; the caller must hold `project.orchestrator_role` for `--project` at this moment, else `refused: poster — <caller> does not hold <role>` (the task is never stored). The newest `role_event` for that role, which names the caller as `new_holder`, is recorded on the task as `poster_event` (R-3).
2. Spec: run in the caller's cwd `git rev-parse --show-toplevel`, `git rev-parse HEAD:<PATH>` (the blob), `git rev-parse HEAD` (the commit), `git status --porcelain -- <PATH>` (must be empty: `refused: spec has uncommitted changes`), `git remote get-url origin` (the repo), and `git branch -r --contains HEAD` (non-empty, else `refused: spec commit is not on origin; push first (or --local, recorded)`). With `@BLOB` given, it must equal the resolved blob. Record `spec_path, spec_blob, spec_commit, spec_repo, spec_local`.
3. Room: `room(route)` from `meters.py` → `(kind, value, detail)` with kind `measured | estimate | unknown`. Print one line first: `team: estimate 31 % room (method: cost-ratio, 2026-10-15T09:02Z)` or `credits: balance $112.43 (billing page, 2026-10-10T17:40Z; correction 1.00)` or `max: unknown (missing: fable share)`. Refuse when kind is `measured` or `estimate` and value < `routing_floor_pct` (fact, default 15), unless `--force` (`forced = 1`). For `credits`, the value is dollars against `credits_floor_usd` (default 10). `unknown` posts and records `room_at_post = 'unknown: <detail>'`.
4. `cross_account = 1` when `route != caller.account`.
5. `BEGIN IMMEDIATE`; `seq = next_seq()`; insert `task(state='posted', poster_role, poster_event, …)` and `task_event('posted')`; `COMMIT`. Print `t12 posted (team-session, team, opus) spec meta/tasks/t-0012.md@<blob8> cross-account`.

### `list` and `show`
`--mine`: for a worker or job, tasks with `route_account = my account`, `executor_kind = my executor_kind`, state `posted`, plus tasks I claimed; for a seat, tasks I posted. `--open`: not in a terminal state. `--reported`: `reported`, posted by me or by a predecessor in a role I hold now. `--stale`: computed stale (below). Columns: `id state executor route model poster claimed_by reported_at verified_by spec`. `--json` rows carry exactly these keys: `id, state, project, executor_kind, route_account, model, from_identity, poster_role, poster_event, spec_path, spec_blob, spec_commit, spec_local, room_at_post, forced, cross_account, claimed_by, claimed_label, claimed_at, reported_by, reported_label, reported_at, report_ref, verified_by, verified_label, verdict, evidence_ref, verified_at, supersedes, superseded_by, at, stale` (the gate's block V reads `id`, `state`, `executor_kind`, `spec_path`, `reported_by`, `reported_label`, `verified_by`, `verified_label`). `show` prints every column, the events, and the computed `stale` flag. **The body is a pointer**: `show` never prints the spec's content (DR-102); it prints `read it with: git -C <checkout> cat-file -p <blob>`.

Computed stale (DR-100): state `claimed` or `working`, and (the claimer's session reads `gone`, or `now > claimed_at + grace_s`). `list` shows `stale*` for these; `repost` writes `state='stale'` on the old row.

### `claim` (DR-100, DR-102)
1. Refuse unless `caller.account == route_account` (`refused: account — task routed to team, you are max`) and `caller.executor_kind == executor_kind` for workers and jobs; a seat may claim only `executor_kind = subagent` tasks it posted itself (`--label` names the subagent; the claim is attributed `seat/label`).
2. **The poster check** (RULES §1 condition 2): the task's `poster_event` must be a `role_event` row whose `role` is `poster_role` and whose `new_holder` is `from_identity` (R-3: the check keys on the event, so a post and a handoff that fall in the same second are told apart; no such row, or one for another role or holder → refused). Else write `task_event('refused:poster')` and print `refused: poster — role_event <poster_event> does not make <from_identity> the holder of <role>`; do not claim. A later handoff of the role does not refuse the task (V-10).
3. CAS: `UPDATE task SET state='claimed', claimed_by=?, claimed_session=?, claimed_label=?, claimed_at=? WHERE seq=? AND state='posted'`; rowcount 0 → `refused: t12 is <state> (claimed by <x> at <at>)`.
4. Print `t12 claimed by libs-worker_1 at <at>; poster nitpick-libs_18 (libs-seat); spec meta/tasks/t-0012.md@<blob> — re-read it from git at that blob before working`. Here `<blob>` is the **full 40-hex blob id** (`post` prints the 8-character short form; the claim line prints the whole id, which the gate's out file needs and which the worker's setup prompt asks it to check against the poster, R-10).

### `progress`, `report`, `verify`
- `progress`: claimer only; `state='working'`; event with the note.
- `report`: claimer only (identity match; for `subagent` the `--label` must equal `claimed_label`); state `claimed|working → reported`; records `report_ref` (a path or commit; the verifier reads it), `reported_by`, `reported_label`.
- `verify` (DR-101): refuse when `caller.identity == reported_by` and (`reported_label IS NULL` or `--label == reported_label`): `refused: the reporter cannot verify`. Only the poster, the poster's labelled subagent, **the current holder of `poster_role`** (or its labelled subagent), or `author` may verify (`refused: not the poster or the role's holder`). State `reported → verified | rejected` by the verdict; records `verified_by`, `verified_label`, `evidence_ref`. Prints `t12 verified pass by nitpick-libs_19/verifier-2 (evidence <ref>)`.

### `repost` and `withdraw`
`repost`: the poster or the current holder of `poster_role`; the old task must be computed stale or `rejected`; writes `state='stale'` (or leaves `rejected`), creates a new task copying the spec and route with `supersedes = old`, sets `superseded_by` on the old; prints both ids. `withdraw`: the poster, the current holder of `poster_role`, or `author`; `posted|claimed|working → withdrawn` with the reason as an event (so a task left in `working` by a failed credits run, §2, can be closed without waiting for the grace).

## 2. The credits runner wrapper (DR-104): `src/dio_credits_run.sh`

```sh
#!/bin/sh
# dio_credits_run.sh TASK JOB [MODEL] [MAX_TURNS]: claim TASK for a credits job, run the unchanged
# credits runner, report the output path. Runs from the author's terminal or a seat's Bash.
# Overrides, for tests only: DIO_CREDITS_DIR (the credits directory), DIO_CREDITS_RUN (the runner),
# DIO_SRC (the dio source directory). DIO_HOME selects the store, as everywhere.
set -eu
TASK=${1:?task id}; JOB=${2:?job name}; MODEL=${3:-sonnet}; TURNS=${4:-80}
DIO="python3 -I ${DIO_SRC:-/home/randy/Workspace/REPOS/diogenes/src}/dio.py"
CREDITS=${DIO_CREDITS_DIR:-/home/randy/Workspace/REPOS/nitpick-libs/.internal/credits}
RUN=${DIO_CREDITS_RUN:-$CREDITS/run.sh}
OUT=$CREDITS/out/$JOB.md
# the runner's own pre-checks, repeated here so a run that would exit before spending claims nothing
[ -f "$CREDITS/jobs/$JOB.md" ] || { echo "no job file $CREDITS/jobs/$JOB.md; nothing claimed, nothing spent" >&2; exit 2; }
[ ! -e "$CREDITS/out/$JOB.json" ] || { echo"out/$JOB.json exists; pick a new job name; nothing claimed, nothing spent" >&2; exit 2; }
SID="job-$JOB-$(date -u +%Y%m%dT%H%M%SZ)"
$DIO register --name "credits:$JOB" --session "$SID" --how runner --account credits --executor credits-job --pid $$ --model "$MODEL"
$DIO --session "$SID" task claim "$TASK" || { echo "claim failed; nothing spent" >&2; exit 3; }
T0=$(date +%s)
set +e; "$RUN" "$JOB" "$MODEL" "$TURNS"; RC=$?; set -e
# run.sh exits 0 after an API error or the turn limit (its epilogue always writes out/JOB.md and the
# ledger line), so the CLI's own result JSON decides, not the runner's exit code (R-4)
OK=0
if [ "$RC" -eq 0 ] && [ -f "$OUT" ] && [ "$(stat -c %Y "$OUT")" -ge "$T0" ] \
   && python3 -I -c 'import json,sys;r=json.load(open(sys.argv[1]));sys.exit(0 if not r.get("is_error") and r.get("subtype")=="success" else 1)' "$CREDITS/out/$JOB.json" 2>/dev/null; then
  OK=1
fi
if [ "$OK" -ne 1 ]; then
  $DIO --session "$SID" task progress "$TASK" --note "run failed rc=$RC; no report (out/$JOB.md missing or older than the claim, or out/$JOB.json not a success result)"
  echo "run failed rc=$RC; task $TASK left in working, not reported" >&2
  if [ "$RC" -ne 0 ]; then exit "$RC"; fi; exit 5
fi
LEDGER=$(tail -1 "$CREDITS/LEDGER.md")
$DIO --session "$SID" task report "$TASK" --ref "$OUT" --note "rc=$RC; ledger: $LEDGER"
```

The runner itself is unchanged, passes no `--bare` (DR-98; verified by `grep -c -- '--bare' "$RUN"` printing 0), and the job's model never calls `dio`. A claim that fails stops before any credit is spent; a run that fails, that leaves no output newer than the claim, or whose `out/<job>.json` is not a `success` result is **never reported** (V-3, R-4): the task stays `working` with the failure note, and the orchestrator withdraws or reposts it. The result check is needed because `run.sh`'s last command is its Python epilogue, which writes `out/<job>.md` (error text included) and the ledger line and exits 0 whatever the CLI's exit code was; `is_error` and `subtype` are the CLI's own fields in `out/<job>.json`, and a missing or unparsable file fails the check too. `run.sh`'s own early exits (missing job file, existing `out/<job>.json`) are repeated before the claim so they claim nothing. `stat -c %Y` is GNU coreutils', present here.

## 5. Risks

- **`git branch -r --contains`** is slow on huge repositories; the author's are small. If it exceeds 2 s, use `git merge-base --is-ancestor HEAD origin/HEAD`.
- **A spec in a different checkout than the worker's**: `spec_repo` and `spec_commit` are recorded; the worker fetches. `docs/USING.md` says `git fetch origin && git cat-file -p <blob>`.
- **The wrapper runs `run.sh` from a seat's Bash**: `claude -p` then runs inside that seat's sandbox (firsthand §4); the runner already handles the proxy variables, but it also writes `out/`, `home/`, `config/` and `LEDGER.md` under nitpick-libs' credits directory and reads `~/.config/nitpick-credits/key`, none of which another project's sandbox allows. **From a seat's Bash it works only in the nitpick-libs workbench seat, whose sandbox already allows that tree; from anywhere else, the author runs it from a terminal** (0.0.4.0 step 5). Both are fine for a read-only job.
- **A wrapper registered from a sandbox** records a sandbox pid and `pid_ns` (`--pid $$` is `given`, so the caller's namespace is recorded, 0.0.1.0 step 5); a host-side `who` reads it `unknown`, which is honest (0.0.1.0 step 6).
- **The CLI's result fields**: `is_error` and `subtype` are what `run.sh`'s epilogue itself reads from `out/<job>.json`; if a CLI update renames them, the wrapper fails safe (nothing is reported) and the executor records the new shape.
