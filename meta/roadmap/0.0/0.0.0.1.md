> **Scope:** the practice `ROADMAP.md` "Day zero" gives, written as steps the author runs, plus the three experiments that need the second account (DX-4, DX-5, DX-26) and the DQ-27 memory setup. **Every step is `[author]`**; a seat may prepare files but opens no Team session. This note runs on whatever day the seat arrives; it never blocks a code subcycle.

## 1. The moment the seat exists

1. `[author]` Create the config dir and sign in: `mkdir -p ~/.claude-team && CLAUDE_CONFIG_DIR=~/.claude-team claude` (sign-in flow), in a terminal whose cwd is a throwaway directory, for example `${TMPDIR:-/tmp}/dio-probe-team` (create it; it is the Team probe project). Record the clock.
2. `[author]` In that session: `/status` and `/config`. Record: the organization name, whether you are its Owner, and whether the settings show `allowManagedHooksOnly`, `allowManagedModsOnly`, `disableAllHooks`, `channelsEnabled` or any `permissions.deny` (DQ-4). These answers are written into `meta/research/done/DX-RESULTS-0.0-<date>.md` §DX-5 by the seat when told.
3. `[author]` DX-4 (15 minutes, not blocking): open `claude --name probe-a` in `<P>` on the Max side with `CLAUDE_CONFIG_DIR` **unset** (never set it to `~/.claude` explicitly, [c1 C-12]); in the Team terminal `CLAUDE_CONFIG_DIR=~/.claude-team claude --name probe-b`; in a third shell `ls -la /run/user/1000/cc-socks /tmp/cc-socks-1000 2>&1; claude agents --json; CLAUDE_CONFIG_DIR=~/.claude-team claude agents --json`. In each session `/list-agents`; ask `probe-a` to message `probe-b`. Record whether the other account's session was listed and whether the message arrived. **Whatever the result, Diogenes does not depend on it** (DR-5); if it passes, a pointer-only `SendMessage` ("task file at `meta/tasks/t-0001.md`, commit `abc123`") is the day-zero doorbell (DQ-8).
4. `[author]` DX-5: copy `0.0.0.0.md` §5's `dx3.sh`, `dx3-status.sh` and the DX-2 `dx2.sh` into the Team probe project's `.claude/settings.json` (paths under the Team probe dir). **Before installing any status-line script under the Team config dir, read your existing Max status-line script and confirm whether it writes the fixed path `~/.claude/usage-latest.json`** ([c1 C-4]). The probe status line only tees; it runs no writer of that path. In `probe-b`: type one prompt, run the DX-3 Bash line, `/status`. The seat reads the Team probe logs and records: hooks ran (yes/no), `rate_limits` present (expected absent, [r1b disposition 14]), `cost.total_cost_usd` present, the socket directory used, `session_id` present in the hook.
5. `[author]` DX-26 (optional, 30 minutes, needs Node): skip on day zero unless the build is already waiting on a measured Team meter. If run: the mod from `EXPERIMENTS.md` DX-26 in the Team probe project only; no `$.prompt.submit`, no timer.
6. `[author]` DQ-27: set `autoMemoryDirectory` (or `CLAUDE_CODE_PROJECT_DIR_NAME` with `CLAUDE_CONFIG_DIR` also set, [r1b §5]) in the Team account's user settings to the Max account's project memory directory for `nitpick-libs` (listed in `PROJECT_INDEX.md`). This is a change to **your** settings; the seat does not make it. Record it as a fact in the results file: `memory shared: <path>, <date>`.
