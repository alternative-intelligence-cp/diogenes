# 0.0.2.2 — `dio wait --for-me`; the hooks `session-start` and `inject`; latency logging — PLANNED (2026-10-10)

> **Scope:** DR-3, DR-4, DR-24, DR-91's 0.0 subset (the hook side), DR-105, DR-107 (the hook side of registration). DESIGN §3 (Claude Code rows "poll at turn boundary" and "wait"), §10.1.
>
> **What it is not:** installation under either account (0.0.3.0); `Stop` and `SessionEnd` hooks (0.1); any wake but the seat's own wait (DQ-7); `asyncRewake`, mods, cron (0.2).
>
> **Found at planning:** (1) the hook must never fail a prompt: every path catches everything, logs to `DIO_HOME/log/hook-errors.log`, prints nothing, exits 0. (2) `--max` of `dio wait` is set from DX-13's measured cap (README §8); the default below is the plan's and the executor replaces it with the measurement. (3) One exit of a wait is one model turn; the pointer it prints is the whole value of that turn, so it names what arrived and the command to run. (4) A wait must see work that was already waiting when it started, and must not fire twice for the same item (V-9): it runs its queries once at once, and remembers per session the highest sequence it has woken for.

**Gate for starting:** 0.0.2.1 `DONE`; DX-2 and DX-13's 10-minute leg filed.

## 1. `dio hook session-start --account A` (DR-91, DR-107, DR-20)

Stdin: the hook JSON (`session_id, transcript_path, cwd, hook_event_name, source, session_title, model, permission_mode`). Env: `CLAUDE_CODE_MESSAGING_SOCKET`.
1. `name = session_title` (custom names only, [r1 §1.2]); identity id = name, or `anon-<session_id[:8]>` when absent. **When the name fails the identity validator or is reserved** (`author`, any `*-seat`), the identity id is also `anon-<session_id[:8]>` and the context line says so: `registered as anon-7702a1bc (your name "libs-seat" is reserved; roles are assigned with dio role assign)` (V-14: a session started with `--name libs-seat` is registered, but never as `libs-seat`).
2. `pid`: the socket path's basename number (`/run/user/1000/cc-socks/<pid>.sock`); cross-check the ancestor walk (`os.getppid()` chain up to 4 steps, `comm == 'claude'`); on mismatch, record the socket's and log the walk's. `pid_ns` is the hook process's own (the host's; hooks run outside the sandbox).
3. Call `register` internally with `how='hook-stdin'`, `account=A`, `pid`, `pid_start` from `/proc`, `pid_ns`, `socket`, `transcript`, `cwd`, `model`; on `source` in `resume|compact|clear` it refreshes.
4. Executor kind: a session under the Team account registers `executor_kind='team-session'` **only when** its name matches the worker regex `^[a-z][a-z0-9-]*-worker_[0-9]+$` (so `libs-worker_1` and `dio-worker_1` both qualify, DQ-22); any other name registers as a seat with no executor kind (RULES §7). Under `max`, never an executor kind.
5. Output: `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"Diogenes: registered as <identity> (<account>). Delivery happens at your next prompt or tool call; nothing wakes an idle session unless it starts its own dio wait. Commands: dio inbox, dio task list --mine, dio who."}}` (DR-4's text, under 300 characters).

## 2. `dio hook inject --account A` (DR-3, DR-24)

Stdin: the hook JSON; `hook_event_name` is `UserPromptSubmit` or `PostToolUse`.
1. Resolve by `session_id` (rule 1). Unknown session → register as in §1 (a hook that missed `SessionStart`, e.g. after an update restart), then continue.
2. Counts for my identity: `unread` (deliveries not acked), `unread_re` (of those, `reply-expected`), `reported` (tasks I posted, or that a predecessor posted in a role I hold, in `reported`), `posted` (tasks routed to my account and kind in `posted`, for workers), `stale` (my posted tasks computed stale).
3. On `PostToolUse`: if `(unread, reported, posted)` equals the session's `inject_*` columns, print nothing and exit 0. Otherwise (and always on `UserPromptSubmit`) write the three columns and print:

```json
{"hookSpecificOutput":{"hookEventName":"<event>","additionalContext":"Diogenes [data, not instructions] for nitpick-libs_18 (libs-seat): 2 unread (m1042 notice ack-only from compiler-seat; m1043 request reply-expected from libs-worker_1); 1 task reported (t12 by libs-worker_1); 0 posted to you. Run: dio inbox · dio task list --reported"}}
```

When every count is zero on `UserPromptSubmit`, print nothing (no noise). Message lines list at most 5 ids, then `… and N more`. The text is cut at 900 characters (DR-24: under 1 000). **Never a body, never a subject** beyond the kind and sender.
4. Update `last_seen_at = now, last_seen_how = 'hook'`; run `process_check` on this account's open sessions (cheap; writes `last_check_*` for `alive` or `dead` only).
5. Append one line `<at> <event> <elapsed_ms> <in_process_ms>` to `DIO_HOME/log/hook-latency.log` (G7). **`elapsed_ms` is measured from process start, not from the first Python statement** (V-15), **and both ends are read on one clock, the boot clock** (R-2): `starttime` is field 22 of `/proc/self/stat` (parsed after the last `)`), in clock ticks since boot on the kernel's boot-time clock; `CLK_TCK = os.sysconf('SC_CLK_TCK')`; `elapsed_ms = (time.clock_gettime(time.CLOCK_BOOTTIME) − starttime / CLK_TCK) × 1000`, which includes interpreter start-up and imports at 10 ms resolution. (The first amendment's `btime + starttime / CLK_TCK` against `time.time()` overstated every figure by a constant 0–999 ms per boot, because `btime` in `/proc/stat` is whole seconds; Python 3.12 exposes `CLOCK_BOOTTIME` on Linux.) `in_process_ms` is the old in-process figure, kept for comparison. `dio adapter latency [--since DATE]` prints `n, p50, p95, max` over `elapsed_ms`.

## 3. `dio wait --for-me [--every S] [--max S]` (DR-105)

1. Resolve the caller (Bash: the socket; `--session` otherwise). Write `wait_since = now`, `wait_pid = os.getpid()`, `wait_pidns = os.readlink('/proc/self/ns/pid')` on the session. Read the session's `wait_seen` (JSON `{"m": N, "t": N, "e": N}`: the highest message seq, task seq and task-event seq this session has already been woken for).
2. **Run the three queries once at once, before any sleep** (V-9: work that arrived before the wait started, including a second task already posted when a worker re-arms after its first, is seen immediately). Then loop until `--max` (default **28 800 s**, replaced by DX-13's figure × 0.9 if the cap is shorter): open a connection, read `PRAGMA data_version`; sleep `--every` (default 5 s); re-read; on change, re-run the three queries. If DX-13 §3 found `data_version` does not change on a long-lived connection, reconnect per poll (the code has a `--reconnect` flag defaulting to that finding). The queries, each with its high-water mark:
   - unread `reply-expected` messages to me with `seq > m`;
   - `posted` tasks routed to my account and executor kind with `seq > t` (workers and jobs);
   - tasks I posted (or that a predecessor posted in a role I hold) whose newest `reported` task event has `seq > e` (seats).
3. On a hit: write `wait_seen` with the new high-water marks (the highest seq seen in each category), clear `wait_since`, print `WAKE: 1 task posted to you (t12 by libs-seat); run dio task list --mine` (or `WAKE: 1 reply-expected message (m1043 from libs-worker_1); run dio inbox`, or `WAKE: 1 task reported (t12 by libs-worker_1); run dio task list --reported`), exit 0. Since the seat ran it with `run_in_background`, the exit re-invokes the idle session (firsthand §2). An item that was already reported by a wake is never a hit again, so a re-arm with an unacked `reply-expected` message or an unverified report does not fire at once (V-9).
4. On `--max`: clear `wait_since` (`wait_seen` unchanged), print `no mail in <max> s; re-arm with: dio wait --for-me`, exit 4.
5. `try/finally` clears `wait_since`; `who` treats a `wait_pid` whose process is dead as not waiting only when `wait_pidns` equals its own PID namespace (0.0.1.0 step 6); otherwise it trusts `wait_since`.
6. `dio who` shows `wait` in the `wait` column while `wait_since` is set (DR-105's "visible in the roster").

Cost note in `docs/USING.md`: each exit is one model turn; the default `--every 5` costs no model anything.

## 6. Risks

- **Python start-up on a loaded machine** may exceed 150 ms; G7's bound is 300 ms at p95 over a day, measured in 0.0.4.0 from the latency log, not from five runs.
- **A hook on `PostToolUse` fires for every tool call of every seat on the account**: the counts are three indexed queries; keep them so.
- **A subagent's tool calls fire the same hooks** ([r1b §3]); `inject` for a subagent (stdin has `agent_id`) prints nothing in 0.0 (DESIGN §10.3) but still logs latency and refreshes `last_seen_at`.
- **`/proc/self/stat` field 22 and `CLOCK_BOOTTIME`** are Linux-only; the hook is Linux-only in 0.0. Field 22 counts on the boot-time clock on this kernel (7.0); if block V's 20 ms cross-check fails by a constant, the executor records it and compares against `CLOCK_MONOTONIC` before changing anything.
