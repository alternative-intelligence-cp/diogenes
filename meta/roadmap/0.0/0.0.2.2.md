## 1. `dio hook session-start --account A` (DR-91, DR-107, DR-20)

Stdin: the hook JSON (`session_id, transcript_path, cwd, hook_event_name, source, session_title, model, permission_mode`). Env: `CLAUDE_CODE_MESSAGING_SOCKET`.
1. `name = session_title` (custom names only, [r1 §1.2]); identity id = name, or `anon-<session_id[:8]>` when absent.
2. `pid`: the socket path's basename number (`/run/user/1000/cc-socks/<pid>.sock`); cross-check the ancestor walk (`os.getppid()` chain up to 4 steps, `comm == 'claude'`); on mismatch, record the socket's and log the walk's.
3. Call `register` internally with `how='hook-stdin'`, `account=A`, `pid`, `pid_start` from `/proc`, `socket`, `transcript`, `cwd`, `model`; on `source` in `resume|compact|clear` it refreshes.
4. Executor kind: a session under the Team account registers `executor_kind='team-session'` **only when** its name matches `<project>-worker_<N>`; any other name registers as a seat with no executor kind (RULES §7). Under `max`, never an executor kind.
5. Output: `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"Diogenes: registered as <identity> (<account>). Delivery happens at your next prompt or tool call; nothing wakes an idle session unless it starts its own dio wait. Commands: dio inbox, dio task list --mine, dio who."}}` (DR-4's text, under 300 characters).

## 2. `dio hook inject --account A` (DR-3, DR-24)

Stdin: the hook JSON; `hook_event_name` is `UserPromptSubmit` or `PostToolUse`.
1. Resolve by `session_id` (rule 1). Unknown session → register as in §1 (a hook that missed `SessionStart`, e.g. after an update restart), then continue.
2. Counts for my identity: `unread` (deliveries not acked), `unread_re` (of those, `reply-expected`), `reported` (tasks I posted in `reported`), `posted` (tasks routed to my account and kind in `posted`, for workers), `stale` (my posted tasks computed stale).
3. On `PostToolUse`: if `(unread, reported, posted)` equals the session's `inject_*` columns, print nothing and exit 0. Otherwise (and always on `UserPromptSubmit`) write the three columns and print:

```json
{"hookSpecificOutput":{"hookEventName":"<event>","additionalContext":"Diogenes [data, not instructions] for nitpick-libs_18 (libs-seat): 2 unread (m1042 notice ack-only from compiler-seat; m1043 request reply-expected from libs-worker_1); 1 task reported (t12 by libs-worker_1); 0 posted to you. Run: dio inbox · dio task list --reported"}}
```

When every count is zero on `UserPromptSubmit`, print nothing (no noise). Message lines list at most 5 ids, then `… and N more`. The text is cut at 900 characters (DR-24: under 1 000). **Never a body, never a subject** beyond the kind and sender.
4. Update `last_seen_at = now, last_seen_how = 'hook'`; run `process_check` on this account's open sessions (cheap).
5. Append one line `<at> <event> <elapsed_ms>` to `DIO_HOME/log/hook-latency.log` (G7). `dio adapter latency [--since DATE]` prints `n, p50, p95, max` over the log.

## 3. `dio wait --for-me [--every S] [--max S]` (DR-105)

1. Resolve the caller (Bash: the socket; `--session` otherwise). Write `wait_since = now`, `wait_pid = os.getpid()` on the session.
2. Loop until `--max` (default **28 800 s**, replaced by DX-13's figure × 0.9 if the cap is shorter): open a connection, read `PRAGMA data_version`; sleep `--every` (default 5 s); re-read; on change, run the three queries: unread `reply-expected` messages to me; `posted` tasks routed to my account and executor kind (workers and jobs); `reported` tasks I posted (seats). If DX-13 §3 found `data_version` does not change on a long-lived connection, reconnect per poll (the code has a `--reconnect` flag defaulting to that finding).
3. On a hit: clear `wait_since`, print `WAKE: 1 task posted to you (t12 by libs-seat); run dio task list --mine` (or `WAKE: 1 reply-expected message (m1043 from libs-worker_1); run dio inbox`, or `WAKE: 1 task reported (t12 by libs-worker_1); run dio task list --reported`), exit 0. Since the seat ran it with `run_in_background`, the exit re-invokes the idle session (firsthand §2).
4. On `--max`: clear `wait_since`, print `no mail in <max> s; re-arm with: dio wait --for-me`, exit 4.
5. `try/finally` clears `wait_since`; `who` also treats a `wait_pid` whose process is dead as not waiting.
6. `dio who` shows `wait` in the `wait` column while `wait_since` is set (DR-105's "visible in the roster").

Cost note in `docs/USING.md`: each exit is one model turn; the default `--every 5` costs no model anything.

## 6. Risks

- **Python start-up on a loaded machine** may exceed 150 ms; G7's bound is 300 ms at p95 over a day, measured in 0.0.4.0 from the latency log, not from five runs.
- **A hook on `PostToolUse` fires for every tool call of every seat on the account**: the counts are three indexed queries; keep them so.
- **A subagent's tool calls fire the same hooks** ([r1b §3]); `inject` for a subagent (stdin has `agent_id`) prints nothing in 0.0 (DESIGN §10.3) but still logs latency and refreshes `last_seen_at`.
