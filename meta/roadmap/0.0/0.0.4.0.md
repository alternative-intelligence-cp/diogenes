## 2. Scripts (`tests/gate/`)

- `messages.sh SIDE PEER N`: sends N messages `dio send PEER --kind request --reply reply-expected --subject "gate SIDE i"`, then waits (poll `dio inbox --count` every 5 s, up to 10 minutes) until N messages from PEER are unread, lists them with `dio inbox`, acks them, and prints `SIDE: sent N, received N, acked N`.
- `tasks_post.sh N EXECUTOR ROUTE [PREFIX]`: `stamp=$(date -u +%Y%m%dT%H%M%SZ)`, PREFIX default `gate`; for i in 1..N writes `meta/tasks/<PREFIX>-<EXECUTOR>-<stamp>-<i>.md` from the template below (unique names, so every call has something to commit, V-12), commits them (`gate: N specs for EXECUTOR`), pushes (step 0b says how), posts each with `dio task post --project diogenes --executor EXECUTOR --route ROUTE --model opus --spec <path>`, and prints `<task id> <spec basename>` per line and, for `credits-job`, the job names the author must create (`<PREFIX>-<stamp>-<i>`).
- **The spec template** (exact text; `<base>` is the file's basename without `.md`):

  for `team-session`:
  ```
  # gate task <base>
  executor: team-session
  do: write the file .internal/gate/out-<base>.txt containing exactly one line, "<base> <blob>", where <blob> is the full spec blob printed by your dio task claim line; then dio task report <id> --ref .internal/gate/out-<base>.txt
  acceptance: grep -qx "<base> $(git rev-parse HEAD:meta/tasks/<base>.md)" .internal/gate/out-<base>.txt
  ```
  for `credits-job` (the job name is `<base>` without its `credits-job-` part, i.e. `<PREFIX>-<stamp>-<i>`):
  ```
  # gate task <base>
  executor: credits-job
  do: none; the credits runner wrapper runs jobs/<job>.md, which says "Reply OK."
  acceptance: grep -q OK /home/randy/Workspace/REPOS/nitpick-libs/.internal/credits/out/<job>.md
  ```
  for PREFIX `gate-reject` (`team-session`): the `do:` line is `do: report at once with --ref none; nothing else` and the acceptance line is `acceptance: false`.

  The acceptance is evaluated at verify time, so the team acceptance can only pass if the worker wrote the blob it was given at claim; it cannot pass vacuously (V-11). `.internal/` is gitignored and both seats' cwd is the same checkout, so the worker's file is where the verifier looks.
- `tasks_verify.sh`: for every task `dio task list --reported --json` returns (mine, or a predecessor's in my role), `blob` from the row, `acc=$(git cat-file -p "$blob" | sed -n 's/^acceptance: //p')`, `sh -c "$acc" > .internal/gate/verify-<id>.log 2>&1`; verdict `pass` on exit 0, else `fail`; runs `dio task verify <id> --verdict <v> --evidence .internal/gate/verify-<id>.log --label gate-verifier` and prints `<id> <v>`.
- `wait_trials.sh N`: the orchestrator side of G6: for i in 1..N, waits until `dio who --json` shows the worker with `wait`, records the clock, posts one task (`tasks_post.sh 1 team-session team`), and polls `dio task show` until `claimed`; prints `trial i: posted <t>, claimed after <s> s`. It types nothing into the worker; the worker's own re-arm after each report is what makes the next trial possible.
- `relay_log.md`: a file both seats append to, one line per gate step, each with `relay: none` or the relay that happened. The worker's setup prompt is logged once as `relay: setup`.
