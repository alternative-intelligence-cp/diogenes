## 1. Commands

```
dio hook status-line --account A [--then CMD]      # stdin: the status-line JSON; stdout: CMD's stdout (or nothing)
dio meters [--json]
dio meters publish --account A                     # same as the hook, for a by-hand paste of the JSON on stdin
dio meters set fable PCT --source author           # DR-56's manual fallback
dio meters set team PCT --source author            # the manual Team estimate (method: author)
dio meters set presence-grace SECONDS | routing-floor PCT | credits-floor USD
dio credits [--json]
dio credits set BALANCE_USD --source "billing page" [--correction FACTOR]
```

### `hook status-line` (DR-55, DR-57)
Reads the JSON (keys per DX-6's results file; the plan's expectation from [r1 §7] and firsthand §3):
- `rate_limits.five_hour|seven_day.{used_percentage, resets_at}` → `meter(account, window, used_pct, resets_at as ISO from epoch, written_at=now, source='status-line', kind='measured')`. Absent → nothing written for that window.
- `model_limits`: for each entry whose name contains `fable` (case-insensitive; the shape is taken from DX-6) → `meter(account, 'model:fable', …)`.
- `context_window.used_percentage`, `cost.total_cost_usd`, `total_input_tokens`, `total_output_tokens` → `context(session_id, account, …, written_at)`.
- `session_id` → if a session row exists, `last_seen_at=now, last_seen_how='status-line'`; it never registers a session (that is `SessionStart`'s).
- Then `process_check` on every open session of this account (writes `last_check_*`), under 2 ms each.
- Then, when `--then` is given, `subprocess.run(CMD, shell=True, input=<the same JSON>)` and print its stdout unchanged. Any exception: log to `DIO_HOME/log/hook-errors.log` and still run `--then`, so the author's status line never breaks because of Diogenes.

**The Team status line writes nothing to `~/.claude/usage-latest.json`** because the wrapper writes to the store per account and `--then` carries only what the author's command does; DX-5 confirmed whether his script hard-codes that path, and 0.0.3.0's Team fragment omits `--then` if it does (the author decides).

### `meters` (DR-55, DR-56, DR-109)
Prints, per account, every window with its age, then the room:

```
max      five_hour 12 % (resets 2026-10-11T03:00Z; written 4 m ago)   seven_day 61 % (resets 2026-10-14T20:00Z; 4 m ago)   fable 68 % (model_limits; 2 h ago)
         room 5.0 = 95 − 61 − 0.5 × (100 − 68)   [sources: status-line 4 m ago, model_limits 2 h ago]
team     five_hour unknown (missing: rate_limits; documented absent for Team)   seven_day estimate 31 % (method: cost-ratio, 2026-10-15T09:02Z)
         room estimate 64 = 95 − 31
credits  balance $112.43 (billing page, 2026-10-10T17:40Z; correction 1.00, 2026-10-10)
```

`room(account)` → `(kind, value, detail)`:
- `max`: needs `seven_day` measured and a Fable value (`model:fable` meter, else the `fable_share` fact); missing → `('unknown', None, 'missing: fable share')` or `'missing: seven_day'`. Value `95 − seven_day − 0.5 × (100 − fable)` (DR-56; the formula is the author's rule, CONSTRAINTS §6). Kind `measured`.
- `team`: a measured `seven_day` meter if one ever appears (DX-26) → `measured`; else the newest `meter_estimate(account='team', window='seven_day')` → `('estimate', 95 − value, 'method: …, <at>')`; else `('unknown', None, 'missing: team estimate (dio meters set team PCT --source author)')`.
- `credits`: the `credits_balance_usd` fact × correction → `('measured', dollars, 'billing page, <at>; correction F')`; absent → unknown.

### The Team estimate, method `cost-ratio` (DR-109)
Computed and stored as a `meter_estimate` row by `hook status-line --account team` and by `meters` when the newest row is older than 10 minutes:
- `window_start = max seven_day resets_at − 7 days` (needs the Max meter; missing → `('unknown', …, 'missing: max seven_day for the ratio')`).
- `max_cost = Σ context.cost_usd` over Max sessions with `written_at ≥ window_start`; `team_cost` the same for Team.
- `ratio = max.seven_day.used_pct / max_cost` (percent per dollar); `team_used = ratio × team_cost × 4` (the author's "roughly a quarter of a Max", CONSTRAINTS §6).
- `inputs` stores every figure as JSON; `method = 'cost-ratio'`. It is labelled `estimate` everywhere and never shown as measured. The manual `set team PCT` writes `method='author'` and wins while newer.

**Cut line (README §6):** if time is short, ship only the manual method and leave `cost-ratio` to 0.1; `meters` then reads `unknown (missing: team estimate …)` until the author sets one, which still satisfies G4.

## 4. Risks

- **DX-6's shapes differ from the plan's** (`model_limits` as a list or a dict keyed by model): read the results file first; the parser accepts both and records which it saw in the `source` column (`status-line:list` / `status-line:dict`).
- **Cumulative session cost** overcounts a session that started before the window; the `inputs` JSON says so (`note: per-session cumulative`).
- **The status line is hot**: any slow path (a process check over hundreds of ended sessions) must filter `ended_at IS NULL` first.
